# Préférences cookies et widgets partenaires

La bannière est commune aux pages publiques. Le bouton « Gérer mes cookies » reste accessible dans le pied de page et sur `/cookies`, y compris pour ouvrir explicitement les réglages depuis l’administration. La bannière ne s’ouvre pas spontanément dans l’administration.

Comportement demandé : les widgets partenaires chargent directement après lecture des préférences du navigateur, sans bouton d’accord dans chaque bloc. En l’absence de choix enregistré, les contenus partenaires sont activés et la mesure des conversions sur le site est désactivée. Le refus des contenus partenaires démonte les cadres, enlève les blocs vides et leurs onglets, et empêche leur chargement aux prochaines visites tant que le choix est conservé. Les images et textes éditoriaux restent affichés. Les liens d’affiliation restent utilisables.

La bannière propose « Tout refuser », « Tout accepter » et « Personnaliser ». Deux catégories sont configurables : contenus partenaires et mesure des conversions GetYourGuide. Le fonctionnement nécessaire est toujours actif. Le cookie first-party `snow_explorer_preferences` conserve les deux choix, une version et la date pendant 180 jours, avec `Path=/`, `SameSite=Lax` et `Secure` sous HTTPS. Aucun secret administrateur n’y est stocké. Si l’écriture du cookie échoue, le choix s’applique en mémoire et un message l’indique ; il ne peut alors pas être garanti à la visite suivante.

Le script GetYourGuide autrefois placé sans condition dans `_document.tsx` est maintenant chargé sur les pages publiques après acceptation de la mesure des conversions. Il ne se duplique pas pendant les navigations React. Retirer cet accord enregistre le refus puis recharge la page : supprimer uniquement la balise ne suffit pas à arrêter les écouteurs éventuellement installés par le SDK. Le retrait ne supprime pas les données déjà transmises ni les cookies que le partenaire a pu déposer.

Dans les blocs d’activités, le conteneur GetYourGuide `data-gyg-widget="activities"` avec un `data-gyg-href` du domaine officiel et un identifiant partenaire valide reçoit automatiquement le chargeur GetYourGuide, dans son iframe isolée. Si le code contient déjà ce même script, il n’est pas ajouté une seconde fois. Le code stocké en base n’est pas modifié. Les autres fournisseurs conservent leur code et leurs origines configurés dans l’administration.

Les widgets restent isolés du document principal. Les scripts inline et les accès au parent restent incompatibles. Les erreurs sont écoutées avant le chargement des scripts partenaires. Aucun changement de schéma de base de données n’est requis.

Cette documentation décrit le comportement technique demandé, sans attester les traceurs réellement utilisés par chaque fournisseur ni leur compatibilité réglementaire. La page `/cookies` décrit le chargement immédiat des contenus et distingue la mesure des conversions.

Vérifications : tests de lecture/expiration du cookie, premier affichage direct, refus persistant, choix par catégorie, ouverture/fermeture au clavier, restauration du focus, retrait des cadres et écouteurs, chargement du script d’analyse sans doublon et détection du conteneur GetYourGuide. Les parcours navigateur utilisent des partenaires simulés ; ils ne remplacent pas une validation avec le service GetYourGuide réel.

Validation locale du 20 octobre 2026 : les 52 fichiers de la suite `npm test` passent, ainsi que `tsc --noEmit` et `npm run build`. Les six tests dédiés aux préférences passent également avec stockage désactivé. Chromium vérifie le premier chargement automatique, le refus conservé après rechargement, la réactivation après changement de rubrique, l’absence de doublon lors de l’ouverture des réglages, la navigation SPA, le retrait de l’analyse avec rechargement, le dialogue mobile à 390 px sans débordement et la page cookies. Aucun `pageerror` n’a été relevé sur ces parcours utilisant des partenaires simulés. Les aperçus ordinateur et mobile ont été contrôlés visuellement.
